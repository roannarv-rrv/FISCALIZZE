# Requisitos nao funcionais

Base: relatório do segundo semestre, seção 2. Numeração original preservada. Classificação por inspeção estática do ZIP, não por teste de execução. Local = demonstrado no navegador; parcial = atendimento incompleto; futuro = não implementado; simulado = sem operação institucional.

| ID | Especificação original | Situação |
|---|---|---|
| RNF01 | Usabilidade O sistema deve permitir que um usuário sem treinamento específico registre uma denúncia após consultar as instruções disponíveis na própria interface. | A validar |
| RNF02 | Usabilidade O sistema deve utilizar linguagem clara, objetiva e adequada ao público da comunidade local. | A validar |
| RNF03 | Usabilidade O sistema deve apresentar mensagens de confirmação, alerta e erro sempre que uma operação for concluída, impedida ou exigir correção. | A validar |
| RNF04 | Responsividade A interface deve funcionar em computadores, tablets e smartphones sem perda das principais funcionalidades. | A validar |
| RNF05 | Acessibilidade Os textos, botões, campos e mensagens devem apresentar contraste e tamanho que favoreçam a leitura e a navegação. | A validar |
| RNF06 | Desempenho Em condições normais de uso, o sistema deve apresentar as telas principais em até 3 segundos após a solicitação do usuário. | A validar |
| RNF07 | Desempenho O sistema deve concluir o registro de uma denúncia em até 5 segundos após o envio dos dados, desconsiderando o tempo de upload de arquivos. | A validar |
| RNF08 | Segurança O sistema deve exigir autenticação para acesso às funções restritas aos usuários cadastrados. | Futuro |
| RNF09 | Segurança O sistema deve controlar o acesso às funções administrativas e de fiscalização por meio de perfis de permissão. | Futuro |
| RNF10 | Privacidade O sistema deve proteger os dados pessoais dos usuários e limitar sua exibição conforme a finalidade da plataforma. | Futuro |
| RNF11 | Integridade O sistema deve preservar o histórico de alterações feitas em uma denúncia, impedindo a exclusão não autorizada desses registros. | Futuro |
| RNF12 | Confiabilidade O sistema não deve concluir o cadastro de uma denúncia quando houver falha na validação dos campos obrigatórios. | Parcial |
| RNF13 | Disponibilidade A futura versão funcional deve permanecer disponível durante as 24 horas do dia, exceto em períodos previamente programados para manutenção. | Futuro |
| RNF14 | Manutenibilidade A organização do sistema deve permitir a inclusão de novas categorias de denúncias sem exigir a reestruturação completa da aplicação. | A validar |
| RNF15 | Portabilidade A aplicação deve ser compatível com os principais navegadores atuais utilizados em computadores e dispositivos móveis. | A validar |
| RNF16 | Evolução A arquitetura prevista deve permitir futura integração com órgãos públicos e serviços de localização ou notificação. | Futuro |
| RNF17 | Armazenamento Os dados das denúncias devem ser armazenados de maneira estruturada, permitindo consultas, filtros e geração de relatórios. | Parcial |
| RNF18 | Arquivos O sistema deve aceitar somente formatos de arquivo previamente definidos e respeitar o limite de tamanho estabelecido para anexos. | Parcial |
