# Requisitos funcionais

Base: relatório do segundo semestre, seção 2. Numeração original preservada. Classificação por inspeção estática do ZIP, não por teste de execução. Local = demonstrado no navegador; parcial = atendimento incompleto; futuro = não implementado; simulado = sem operação institucional.

| ID | Especificação original | Situação |
|---|---|---|
| RF01 | O sistema deve permitir que o cidadão crie uma conta informando, no mínimo, nome, CPF, e-mail e senha. | Futuro |
| RF02 | O sistema deve validar os dados obrigatórios informados durante o cadastro. | Futuro |
| RF03 | O sistema deve permitir que o usuário autenticado realize login e encerre sua sessão. | Futuro |
| RF04 | O sistema deve permitir que o usuário altere seus dados cadastrais. | Futuro |
| RF05 | O sistema deve permitir que o usuário registre uma denúncia ambiental. | Local |
| RF06 | O sistema deve apresentar categorias de ocorrência para classificação da denúncia. | Local |
| RF07 | O sistema deve permitir que o usuário informe a descrição da ocorrência. | Local |
| RF08 | O sistema deve permitir que o usuário informe a localização da ocorrência por endereço. | Local |
| RF09 | O sistema deve permitir que o usuário informe a data ou o período aproximado da ocorrência. | Futuro |
| RF10 | O sistema deve permitir o anexo de imagens, vídeos ou documentos à denúncia. | Parcial |
| RF11 | O sistema deve validar os campos obrigatórios antes de concluir o registro da denúncia. | Local |
| RF12 | O sistema deve gerar um identificador único para cada denúncia registrada. | Parcial |
| RF13 | O sistema deve apresentar uma confirmação após o registro da denúncia. | Local |
| RF14 | O sistema deve permitir que o usuário consulte suas denúncias. | Parcial |
| RF15 | O sistema deve apresentar o status atual de cada denúncia ao usuário. | Simulado |
| RF16 | O sistema deve permitir a consulta de denúncias por categoria, localização, data e status. | Parcial |
| RF17 | O sistema deve apresentar as ocorrências em formato de lista ou mapa, conforme a funcionalidade definida para a versão implementada. | Local |
| RF18 | O sistema deve notificar o usuário quando o status de sua denúncia for alterado. | Futuro |
| RF19 | O sistema deve permitir que o responsável pela fiscalização consulte as denúncias encaminhadas para análise. | Futuro |
| RF20 | O sistema deve permitir que o responsável pela fiscalização registre uma análise da denúncia. | Futuro |
| RF21 | O sistema deve permitir que o responsável pela fiscalização atualize o status da denúncia. | Simulado |
| RF22 | O sistema deve permitir que o responsável pela fiscalização registre observações sobre as providências adotadas. | Futuro |
| RF23 | O sistema deve permitir que o responsável encaminhe a denúncia ao órgão competente. | Futuro |
| RF24 | O sistema deve permitir que o responsável solicite informações complementares ao cidadão. | Futuro |
| RF25 | O sistema deve permitir que o administrador gerencie usuários cadastrados. | Futuro |
| RF26 | O sistema deve permitir que o administrador cadastre, altere e remova categorias de denúncias. | Futuro |
| RF27 | O sistema deve permitir que o administrador consulte e organize denúncias registradas. | Futuro |
| RF28 | O sistema deve permitir que o administrador gere relatórios com dados consolidados das denúncias. | Futuro |
| RF29 | O sistema deve registrar a data, o horário e o usuário responsável por cada alteração administrativa ou de status. | Futuro |
| RF30 | O sistema deve impedir que usuários não autorizados alterem informações de denúncias ou dados administrativos. | Futuro |
